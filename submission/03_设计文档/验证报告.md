# 最终算法验证报告

## 评测方法

- 数据按用户 ID 分组，依次留出 ID0 至 ID5，训练过程不接触被留出用户的数据。
- `up/down` 共用的原始录制只读取一次，并合并两类标签，消除重复文件造成的数据泄漏。
- 事件匹配遵循主办方规则：窗口从当前标签前 0.3 秒开始，到下一标签前 0.3 秒结束。
- 单个动作窗口内，多余输出计为错误预测。
- 排名核心指标采用四种有效手势 F1 的宏平均。

## 延迟

六折正确预测总体平均延迟约为 `313 ms`，低于赛题建议的 2 秒上限。

## 模型与资源

- 模型：120 棵随机森林。
- 最大深度：16。
- 最小叶节点样本数：2。
- 特征数：123 个整数特征。
- 树节点数：427,572。
- 模型数组估算：2,138,340 Byte。
- 最终镜像：text 2,522,640 Byte，data 57,124 Byte，bss 30,132 Byte。
- 链接脚本容量：Flash 3 MB，RAM 256 KB。
- 构建结果：0 errors，0 warnings。

## 一致性验证

随机抽取 40 个 IMU 窗口，对 Python 模型和导出的 C 数组逐树计算投票。120 棵树、427,572 个节点的各类票数完全一致。

## 结论

模型对抬腕和放下具有较高稳定性。短时手势中，pinch 与 clench 的跨用户差异仍是主要误差来源。当前参数在精确率、召回率、延迟和资源之间取得平衡。
